# Созвон 3.7 — безопасность и телефон

## Безопасность

- Первая публикация ключа E2EE требует пароль аккаунта; при включённом 2FA — TOTP. Старые клиенты без пароля получат 401 и должны обновиться.
- Смена ключа требует пароль и TOTP, остальные сессии завершаются.
- Сессии привязаны к секрету устройства: украденный bearer-токен без секрета устройства не работает.
- Все API-запросы, включая загрузку файлов, передают X-Device-Key; сервер хранит только SHA-256.
- Сброс пароля по почте для аккаунта с 2FA требует TOTP-код и не расходует код письма до проверки второго фактора.
- OAuth-аккаунт без пароля не может включить E2EE: сначала нужно задать пароль, иначе ключ не восстановить на новом устройстве.
- Добавлен HSTS для API.
- Добавлен журнал событий безопасности: публикация/смена ключа, сброс пароля, завершение других сессий.
- Key-backup API требует клиент не старше 3.6.8: старые версии не смогут перезаписать Argon2-копию.
- История ключей связана SHA-256-цепочкой; клиент проверяет целостность и кэширует последний корень, чтобы заметить переписывание истории сервером.
- Новые устройства видны в списке сессий; завершение остальных сессий ограничено 24 часами после свежего входа.
- Приватный ключ E2EE находится в main-процессе, renderer не получает privateJwk.
- Старый локальный ключ автоматически импортируется при обновлении.
- Новые резервные копии ключа используют Argon2id; старые PBKDF2-копии поддерживаются.
- Кнопка «Сохранить под текущим паролем» перезаписывает серверную копию текущим паролем.
- Окно восстановления открывается поверх настроек.
- Пароль чувствителен к регистру; глазок показывает/скрывает его корректно.
- Одноразовые WebSocket-тикеты, HTTPS-only API, защита navigation/PiP/permissions и SSRF-защита сохранены.

## Телефон

- Регистрация по номеру телефона и паролю.
- Подтверждение через Telegram Contact Share, без SMS.
- Привязка мобильного номера к существующей учётной записи тем же способом.
- Номер хранится на сервере только в виде HMAC, не в открытом виде.
