# ADR 0002. Переписывание бэкенда на Go

**Статус:** предложено, к обсуждению
**Дата:** 2026-11-03

## Контекст

Сервер «Созвона» — Node 22 + Express 5 + `ws` + `node:sqlite` (WAL), один процесс, Caddy впереди,
LiveKit и coturn рядом. Объём:

- **125 HTTP-маршрутов** в `server/src/api.js` (126 КБ);
- **29 таблиц** SQLite, миграции в `db.js` (67 КБ);
- **67 мест** отправки событий в WebSocket (presence, сообщения, комнаты, звонки);
- 22 модуля: `auth`, `sessions`, `oauth`, `totp`, `e2ee`, `hub`, `perms`, `files`, `backup`,
  `link-preview`, `livekit`, `signaling`, `voice`, `turn`, `mail`, `presence`, `config`;
- зависимости: `express`, `ws`, `nodemailer`, опционально `node-turn`;
- аутентификация: scrypt (`scrypt$salt$hash`), сессии + JWT-секрет, OAuth (Яндекс и др.), TOTP;
- E2EE: публичные ключи, передачи ключей, шифрование сообщений на клиенте;
- медиа: LiveKit JWT (HS256), TURN, сcreencast-сигналинг;
- файлы: аватары, баннеры, обои чата, вложения, раздача `/api/avatars|banners|wallpapers|files`;
- эксплуатация: бэкап-таймер, offsite-выгрузка, health, версия клиента, rate limits.

## Зачем Go

- один статический бинарник: проще деплой и откат, меньше зависимостей;
- предсказуемая память и конкурентность (WebSocket + много соединений);
- строгие типы для протокола и миграций;
- проще сопровождать долгоживущий сервер без пересборки node_modules.

Цена: переписать ~280 КБ логики и удержать **полную совместимость** с клиентами 2.9.6 и 3.0.

## Ограничения (жёсткие)

1. **API не меняется** ни в путях, ни в кодах ответов, ни в форме JSON — иначе старые клиенты ломаются.
2. **Схема БД не меняется** без миграции; старый сервер должен уметь работать с той же базой (для отката).
3. **Семантика E2EE сохраняется**: сервер не видит открытый текст, ключи только передаёт.
4. **WebSocket-протокол** (имена событий, порядок, поля) сохраняется.
5. **Форматы файлов** и пути хранения (`/var/lib/sozvon/{avatars,files,...}`) сохраняются.
6. **Секреты и конфиг**: те же переменные окружения, тот же `secret.key` (иначе сессии и JWT
   инвалидируются), тот же способ выдачи LiveKit-токенов.

## Стратегия: параллельная реализация с контрактными тестами, затем переключение

Не «переписать и однажды включить», а два независимых процесса на одной БД в разное время:

| Фаза | Что делаем | Критерий выхода |
|---|---|---|
| 0. Контракт | Снять «золотые» ответы текущего API (маршрут + вход + ответ) в JSON-фикстуры; зафиксировать формат WS-событий | фикстуры в репозитории, гоняются против Node |
| 1. Каркас | Go: конфиг, SQLite (WAL, те же миграции), логи, health, rate limit, раздача статики | `/api/health`, миграции идемпотентны |
| 2. Аккаунты | регистрация, вход, scrypt-совместимость, сессии, TOTP, OAuth, сброс пароля | e2e-сценарии входа/2FA зелёные на Go |
| 3. Соцграф | контакты, заявки, блокировки, хабы, комнаты, роли, права, приглашения | `e2e-friends`, `e2e-hubs`, `e2e-room` зелёные |
| 4. Сообщения | сообщения, треды, реакции, пины, read state, вложения, обои, баннеры | `e2e-chat`, `e2e-threads`, `e2e-status` зелёные |
| 5. Реальное время | WebSocket, presence, typing, сигналинг, звонки, LiveKit-токены, TURN | `e2e-call`, `e2e-group-call`, `e2e-sfu`, `e2e-ptt` зелёные |
| 6. Операции | бэкапы, offsite, почта, версия клиента, лимиты | бэкап/восстановление на копии БД |
| 7. Переключение | Go на staging-БД → теневой прогон на копии прод-БД → окно переключения | 48 часов без ошибок, откат одной командой |

## Стек Go (предложение)

- HTTP: `chi` или `echo`; WebSocket: `coder/websocket` (или `nhooyr.io/websocket`);
- БД: `modernc.org/sqlite` (чистый Go, без cgo) — совместим с файлом SQLite;
- JWT: `golang-jwt/jwt/v5`; пароли: `golang.org/x/crypto/scrypt` (те же параметры, что в Node);
- почта: `net/smtp` или `wneessen/go-mail`; LiveKit-токены: `livekit/server-sdk-go`;
- миграции: те же SQL-файлы, применять через `embed` + таблицу версий;
- логи: `log/slog`; конфиг: те же env-переменные;
- тесты: `testing` + httptest + контрактные фикстуры из фазы 0.

## Риски

| Риск | Смягчение |
|---|---|
| Скрытые договорённости API (порядок полей, коды 404/403) | золотые фикстуры + прогон **обоих** серверов на одном наборе |
| E2EE-нюансы (передачи ключей, доверие устройств) | отдельный набор тестов, ручная проверка двух клиентов |
| Гонки WebSocket/presence | тесты на двух-трёх клиентах одновременно, сравнение с Node |
| Откат | старый Node-процесс остаётся, БД совместима, переключение Caddy одной строкой |
| Дублирование фиксов | до переключения фиксим только Node, Go догоняет; после — наоборот |

## Оценка

По объёму: 125 маршрутов + 67 событий + 29 таблиц. Реалистично **6–9 недель** при одном
разработчике без отрыва от текущих задач 3.0, либо **3–4 недели** при полной загрузке.
Первый полезный результат (фазы 0–2) — около недели: каркас, аккаунты, контрактные тесты.

## Решение

Начать с фаз 0–1 (контракт + каркас), не трогая прод. Переключение — только после зелёного
полного e2e на Go и теневого прогона на копии прод-БД.
