# ADR 0001. Жидкое стекло и фронтенд: остаёмся на Electron

**Статус:** принято
**Дата:** 2026-11-03

## Контекст

В теме «Жидкое стекло» не было настоящего преломления: кромка и блик рисовались светом.
Причина была сформулирована как «Electron не умеет `backdrop-filter: url(#…)`». Это оказалось
**неверно**.

Контрольный опыт (`_tools/refraction-test.html` и `_tools/lens-prototype.html`, Electron 45,
Chromium 156):

- `getComputedStyle` возвращает `backdrop-filter: url("#lens") blur(7px) saturate(1.6)` — фильтр принят;
- на скриншоте видно искажение полос фона под поверхностью, то есть `feDisplacementMap` работает;
- карта смещения строится на canvas, отдаётся в `feImage` как PNG, применяется через
  `feDisplacementMap` (R/G — вектор, A — маска).

Так же устроен референс: в liqui.design (`/docs/handbook/glass`) сказано, что полная рефракция
есть **именно в Chromium**, а Safari и Firefox откатываются на frosted blur. Разделение слоёв
(blur — на одном, displacement — на другом) нужно, чтобы размытие не «включалось» после декода карты.

## Решение

1. **Фронтенд не меняем.** Electron — это Chromium; смена оболочки на Tauri ничего не даст:
   на Windows это тот же WebView2/Chromium, на macOS/WebKit и Firefox рефракция как раз пропадёт.
2. **Рефракцию внедряем по схеме референса:**
   - карта смещения из canvas (SDF скруглённого прямоугольника → нормали), кэш по размеру и оптике;
   - `feImage` + `feDisplacementMap` в общем скрытом `<svg>`-реестре;
   - два слоя: базовый blur на поверхности, displacement — на дочернем слое;
   - размеры брать из `ResizeObserver.contentRect` / `offsetWidth`, не из `getBoundingClientRect`
     (иначе карта «запекается» неверной — это отдельно предупреждает референс).
3. **Порядок внедрения:**
   - пилот на модальных окнах, меню, поповерах, карточке профиля (их мало, они крупные);
   - затем панели (сайдбар, чат, участники);
   - кнопки и мелкие контролы — только если пилот выдержит бюджет кадров.
4. **Деградация и доступность:** при `prefers-reduced-transparency` — сплошной тинт без фильтров;
   при неподдержке — нынешний световой вариант (кромка + блик).
5. **Бюджет:** кэшировать карты, генерировать в полразрешения для поверхностей > 180×180,
   не ставить больше 3–4 крупных фильтров одновременно, замерять `requestAnimationFrame` до/после.

## Альтернативы

| Вариант | Оценка |
|---|---|
| Tauri (Windows) | WebView2 = Chromium: те же возможности и ограничения, плюс переезд. Смысла нет |
| Flutter / Compose / SwiftUI | настоящие шейдеры и линза гарантированы, но это переписывание всего интерфейса |
| WebGL-слой (Pixi/three) | можно, но получаем второй рендер-конвейер и дублирование ввода |
| Windows Mica/Acrylic (`setBackgroundMaterial`) | настоящий материал ОС, но без линзы и только на Windows 11; хорош как фон окна, не как замена стеклу контролов |
| macOS vibrancy | то же для macOS, только фон окна |

## Последствия

- Работа над стеклом продолжается в текущем стеке; меняется только способ рисования кромки.
- Нужен новый модуль (условно `glass-lens.js`) и проверка производительности на слабых машинах.
- В DESIGN-SYSTEM.md раздел «Материал стекла» дополняется: рефракция доступна, но пока не внедрена.
