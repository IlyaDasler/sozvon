# 3.8: формат сообщений v2 и состояние ratchet

## Конверт

```json
{
  "v": 2,
  "conv": "dm:1-2",
  "from": 1,
  "x3dh": {
    "identityPublic": "base64",
    "ephemeralPublic": "base64"
  },
  "ratchet": {
    "dh": "base64",
    "n": 0,
    "iv": "base64",
    "ct": "base64"
  }
}
```

- `v2` — только личные сообщения на первом этапе.
- Комнаты и файлы остаются v1, пока не готов multi-device.
- Сервер хранит конверт как непрозрачный `enc`, не зная ключей.

## Установка сессии

1. Отправитель получает prekey bundle получателя.
2. Проверяет подпись сервера.
3. Считает X3DH root и ephemeralPublic.
4. Инициализирует ratchet.
5. Первое сообщение содержит `x3dh`; получатель считает тот же root.
6. Дальше сообщения идут только с ratchet-заголовком.

## Состояние

- Хранится в utility-процессе.
- Экспорт/импорт — только через utility IPC.
- На диске — отдельный файл, зашифрованный safeStorage.
- При потере состояния сообщение с `x3dh` может пересоздать сессию; старые сообщения остаются v1.

## Совместимость

- 3.7 и старее не читают v2.
- v2 включается только для собеседника с поддержкой 3.8.
- Для старых — v1 и предупреждение.
- История не перешифровывается.

## Multi-device

- У каждого устройства своё ratchet-состояние.
- X3DH bundle — на устройство, не на пользователя.
- Сервер хранит несколько prekey bundles с deviceId.
- Это следующий этап после личных сообщений.

## Тесты

- v1 и v2 в одной переписке;
- перезапуск с сохранённым состоянием;
- потеря состояния и повторный X3DH;
- подмена x3dh/ratchet;
- старый клиент не получает v2.
