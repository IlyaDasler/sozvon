# Резервная копия ключа шифрования

## Зачем

Раньше ключ профиля жил только на одном устройстве, и на новом устройстве его
приходилось переносить вручную кодом. Теперь для аккаунтов с паролем ключ
автоматически сохраняется на сервере в запечатанном виде и так же автоматически
восстанавливается при входе.

## Поток

1. При входе с паролем клиент отправляет пароль на сервер (как и при обычном
   входе) и просит `POST /api/key-backup/read`.
2. Сервер проверяет пароль и отдаёт `salt`, `iv`, `ct`, `iterations`.
3. Клиент выводит ключ из пароля: PBKDF2-HMAC-SHA256, 310 000 итераций,
   `AES-256-GCM`, AAD `sozvon-key-backup-v1|<userID>`.
4. Если копии нет, но локальный ключ уже есть — клиент запечатывает его паролем
   и сохраняет через `PUT /api/key-backup`. При первом входе новый ключ
   создаётся и сразу сохраняется.
5. На новом устройстве после входа по паролю копия открывается и становится
   активным ключом. Ручной код больше не нужен.

Сервер хранит только шифротекст. Он не знает пароль в открытом виде (кроме
момента проверки входа, как и раньше) и не может открыть копию без него.

## Смена и сброс пароля

- **Смена пароля в настройках:** после успешной смены клиент перезапечатывает
  текущий ключ новым паролем и обновляет копию. Если обновление не удалось,
  клиент покажет предупреждение; при следующем входе с новым паролем копия
  обновится с локального ключа.
- **Сброс пароля по почте:** старую копию нельзя открыть новым паролем. Если на
  устройстве остался локальный ключ, он будет перезапечатан новым паролем. Если
  локального ключа нет — остаётся ручной перенос: математически восстановить
  ключ из одного нового пароля невозможно.

## Ограничения

- **OAuth без пароля (Яндекс):** deriving key from OAuth provider secret is not
  possible without giving the server the ability to decrypt. Для таких аккаунтов
  остаётся ручной перенос, пока пользователь не задаст пароль в настройках;
  после этого автоматическая копия включается.
- **Существующие аккаунты:** копия появится после первого входа в обновлённый
  клиент на устройстве, где уже есть ключ. До этого новое устройство попросит
  ручной перенос.
- **Сервер и пароль:** модель доверия не меняется — сервер и раньше принимал
  пароль для входа. Он не хранит пароль и не хранит ключ в открытом виде.
  Резервная копия защищает от чтения базы сервера без пароля, но не от
  компрометации клиента в момент ввода пароля.

## API

```text
POST /api/key-backup/read   { password } -> { salt, iv, ct, iterations, updatedAt }
PUT  /api/key-backup        { password, salt, iv, ct, iterations } -> { ok: true }
```

Оба маршрута требуют авторизацию, проверяют пароль и имеют отдельный лимит
попыток. Для аккаунтов без пароля возвращается 403.
