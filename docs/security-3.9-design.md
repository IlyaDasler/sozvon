# Безопасность 3.9: utility-процесс и Double Ratchet

## 1. Threat model

Защищаемся от:

- XSS/подмены renderer-кода;
- кражи bearer-токена;
- компрометации main-процесса без доступа к OS-хранилищу;
- переписывания серверной истории ключей;
- чтения старых сообщений после утечки текущего ключа переписки.

Не защищаемся от:

- полностью скомпрометированной ОС/учётной записи;
- физического доступа к разблокированному ПК;
- вредоносного обновления, подписанного нашим ключом.

## 2. Utility-процесс

### Архитектура

- `identity-worker` — отдельный процесс, единственный владелец privateJwk.
- Main-процесс:
  - читает/пишет зашифрованный файл через safeStorage;
  - не хранит privateJwk после передачи worker'у;
  - проксирует узкий IPC.
- Renderer:
  - получает только publicKey;
  - операции: `openConversationKey`, `wrapBackup`, `unwrapBackup`;
  - нет доступа к privateJwk.

### Ограничение decryption-oracle

- worker принимает только sealed-ключи, полученные от сервера, и проверяет конверт;
- отдельный лимит на число открытых переписок в минуту;
- аудит каждого открытия без содержимого;
- массовая расшифровка/экспорт требуют подтверждения пользователя;
- при XSS нельзя выгрузить ключ, но можно просить расшифровку — это остаточный риск, его снижаем подтверждением и лимитами.

### Миграция

- старый `e2ee-identity.bin` импортируется один раз;
- privateJwk передаётся worker'у и стирается из main;
- файл переписывается в новый формат.

## 3. Double Ratchet

### Протокол

- X3DH: identity key + signed prekey + one-time prekey.
- Double Ratchet: DH-ratchet + symmetric chain.
- Заголовок сообщения: версия, ratchet public key, previous chain length, message number, conversation id.
- AAD: conversation, epoch, sender, message number.
- Старые сообщения остаются в v1; новые — v2.
- Ключи v2 не пересекаются с v1.

### Multi-device

- у каждого устройства своя ratchet-сессия;
- сервер хранит только публичные prekey bundles;
- новый участник получает текущий ключ переписки через существующий механизм, затем начинает ratchet.

### История

- старые сообщения не перешифровываются;
- v1-ключи сохраняются только для чтения истории;
- новые сообщения используют v2;
- удаление старых chain keys после использования.

## 4. Тесты

- v1-сообщения читаются после обновления;
- v2: порядок, пропуски, повтор, подмена AAD;
- новое устройство;
- несколько устройств;
- backup/restore;
- XSS-симуляция: renderer не получает privateJwk;
- лимиты open.
