# Подпись и автообновление для macOS

## Коротко

Windows обновляется сам уже сейчас: установщик NSIS + `latest.yml`, подпись для этого не нужна.

На macOS **без сертификата Apple автообновление невозможно**: обновление ставит системный
фреймворк Squirrel.Mac, и он проверяет подпись новой версии — она должна совпадать с подписью
уже установленного приложения. Неподписанное приложение обновить нельзя, это ограничение
платформы, а не нашего кода.

## Что нужно

1. **Apple Developer Program** — 99 $/год, оформляется на физическое лицо или компанию.
   Без него нельзя выпустить сертификат типа *Developer ID Application*.
2. В кабинете разработчика создать сертификат **Developer ID Application**, выгрузить
   `.p12` (с паролем).
3. Создать **app-specific password** для Apple ID (appleid.apple.com → «Пароли приложений») —
   нужно для нотаризации.
4. Узнать **Team ID** (в кабинете разработчика, вверху справа).

## Что добавить в GitHub (Settings → Secrets and variables → Actions)

| Секрет | Что это |
|---|---|
| `MAC_CERT_P12` | сертификат `.p12` в base64: `base64 -i cert.p12 \| pbcopy` |
| `MAC_CERT_PASSWORD` | пароль от `.p12` |
| `APPLE_ID` | Apple ID, под которым оформлен аккаунт |
| `APPLE_APP_SPECIFIC_PASSWORD` | пароль приложения из шага 3 |
| `APPLE_TEAM_ID` | Team ID из шага 4 |

После этого нужно включить нотаризацию в `client/package.json`:

```json
"mac": {
  "hardenedRuntime": true,
  "notarize": true
}
```

и пересобрать релиз. Сборка уже передаёт эти секреты в `electron-builder`
(`.github/workflows/build.yml`, job `mac-builder`).

## Что изменится для людей

- Пропадёт предупреждение «разработчик не проверен» — приложение будет открываться обычным
  двойным щелчком.
- Заработает автообновление: приложение само скачает и поставит новую версию, как в Windows.

## Почему без сертификата бывает «приложение повреждено»

На Apple Silicon macOS требует, чтобы у любого кода была хоть какая-то подпись. Если сборка
вообще без подписи, система показывает не «неизвестный разработчик», а «приложение повреждено,
переместите в Корзину» — и `xattr` тут не помогает, потому что дело не в карантине.

Поэтому в сборке появился хук `client/scripts/after-pack.js`: он подписывает `.app` адхок-подписью
(`codesign --force --deep --sign -`) до упаковки в dmg и zip, а затем проверяет подпись
(`codesign --verify --deep --strict`). Если настоящий сертификат есть (`CSC_LINK`), хук ничего
не делает.

Ручное лечение уже установленного приложения:

```
sudo xattr -cr /Applications/Sozvon.app
sudo codesign --force --deep --sign - /Applications/Sozvon.app
```

## Пока сертификата нет

Работает свой механизм (`client/mac-update.js`): приложение берёт zip последнего релиза с GitHub,
снимает карантин, подменяет `.app` и перезапускается сам.

Цена такого способа:
- после каждого обновления macOS заново спрашивает разрешения (микрофон, камера, экран,
  «Универсальный доступ») — они привязаны к подписи;
- если папка с приложением недоступна на запись, обновление не пройдёт — тогда человек
  скачивает новую версию вручную;
- первый запуск каждой новой копии может потребовать «Открыть» через правую кнопку.

С сертификатом всё это уходит: работает штатный Squirrel.Mac, разрешения сохраняются,
предупреждений нет.
