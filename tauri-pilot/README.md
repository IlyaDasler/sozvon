# Tauri-пилот «Созвона»

Пилот не заменяет Electron и не подключён к основному приложению. Цель — проверить
на реальном Windows-раннере размер, запуск и качество анимаций системного WebView2
на не-медийном экране (настройки профиля).

## Состав

- `src-tauri/` — минимальное Tauri 2-приложение на Rust;
- `ui/` — тот же подход HTML/CSS, что в Electron: тёмная стеклянная карточка,
  поля, вертикальная навигация, hover/active и `backdrop-filter`.

Медиастек (WebRTC, LiveKit, E2EE, захват экрана, `MediaRecorder`) сюда намеренно
не переносился: это отдельная проверка с высоким риском.

## Сборка

```powershell
cd src-tauri
cargo build --release
```

Результат: `src-tauri/target/release/sozvon-pilot.exe`.

## Замеры

- размер release-бинарника: **8.3 МБ** (Electron-установщик ~118 МБ);
- запуск в текущей среде DSH: **не удалось** — Tauri/WebView2 возвращает
  `Failed to setup app: Отказано в доступе (os error 5)` до создания окна.
  Это ограничение окружения/WebView2, а не вывод о продукте; для честного
  замера памяти и FPS пилот нужно запустить на обычной Windows-сессии.
- Исходный HTML-экран и анимации собираются, приложение компилируется.

## Вывод

Пилот подтверждает, что не-медийные экраны на Tauri собрать можно, но для
«Созвона» это не даёт автоматического выигрыша в анимациях: на Windows используется
WebView2, а на macOS — WKWebView с другими возможностями WebRTC/захвата экрана.
Решение о миграции принимать только после реального замера FPS/памяти и отдельного
прототипа звонка; в 3.x основной клиент остаётся на Electron.
