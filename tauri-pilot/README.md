# Tauri-пилот «Созвона»

Пилот не заменяет Electron и не подключён к основному приложению. Цель — проверить
на реальном Windows-раннере размер, запуск и качество анимаций системного WebView2
на не-медийном экране (настройки профиля).

## Состав

- `src-tauri/` — минимальное Tauri 2-приложение на Rust;
- `ui/` — тот же подход HTML/CSS, что в Electron: тёмная стеклянная карточка,
  поля, вертикальная навигация, hover/active и `backdrop-filter`.

Медиастек (WebRTC, LiveKit, E2EE, захват экрана, `MediaRecorder`) сюда намеренно
не переносился: это отдельная проверка с высоким риском.

## Сборка и запуск

```powershell
cd src-tauri
cargo build --release

$env:SOZVON_PILOT_DATA = "$PWD\..\webview-data"
.\target\release\sozvon-pilot.exe
```

`SOZVON_PILOT_DATA` задаёт папку WebView2. Если её не задать, используется `%TEMP%`;
в урезанных сессиях Windows `%TEMP%` может быть недоступен (Tauri выдаёт `os error 5`).

## Замеры (Windows 11, WebView2 156)

- размер release-бинарника: **8.3 МБ** (Electron-установщик ~118 МБ);
- процесс Tauri + дочерние WebView2: **331.7 МБ** суммарного Working Set (7 процессов);
- анимация: **122 FPS** (2-секундный замер `requestAnimationFrame`);
- старт скрипта интерфейса: **16 мс** (не полный холодный старт процесса);
- окно настройки профиля рисуется, `backdrop-filter` и hover/active работают;
- при первом запуске Windows показывает SmartScreen для неподписанного бинарника —
  в продукте это решается подписью, как у установщика.

## Вывод

Пилот подтверждает: не-медийный экран на Tauri собрать можно, размер установщика
меньше, анимации в WebView2 плавные. Но суммарная память с WebView2 уже **331 МБ**,
а для звонков по-прежнему нужны WebRTC/захват экрана/E2EE, которые на WKWebView
macOS придётся переписывать. В 3.x основной клиент остаётся на Electron.
