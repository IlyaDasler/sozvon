# Mobile UI Quality

Мобильная версия — не уменьшенный десктоп. Проверяем сценарий и форм-фактор, а не только ширину.

## Референсы

- **Material 3**: top app bar, bottom navigation, navigation rail, modal bottom sheet, 48 dp touch targets, safe areas.
- **Telegram Android**: компактный список чатов, один экран = одно действие, нижние вкладки на телефоне, split view на планшете.
- **Discord Android**: server rail → channel list → chat, нижний лист действий вместо hover-иконок.
- Не копировать бренд и функции; брать принципы навигации и плотности.

## Форм-факторы

| Устройство | Ширина | Высота | Режим |
|---|---|---|---|
| Маленький телефон | 320–359 | 480–700 | compact, bottom nav |
| Телефон | 360–599 | 640–999 | compact, bottom nav |
| Телефон боком | 600–900 | **< 620** | compact, bottom nav; **не Workspace** |
| Флип раскрыт | 360–480 | 800–1000 | compact, bottom nav |
| Фолд снаружи | 300–400 | 700–950 | compact, bottom nav |
| Фолд раскрыт | 600–900 | ≥ 620 | Workspace: rail + rooms + chat |
| Планшет | ≥ 840 | ≥ 620 | Workspace / три зоны |

**Workspace включается только при ширине ≥ 640, высоте ≥ 620 и aspect-ratio ≤ 1.35.** Одной ширины недостаточно: 844×390 — телефон боком.

**Флип раскрыт — высокий телефон, а не планшет.** Workspace на нём запрещён. Экран обложки флипа требует нативного слоя; PWA не должен притворяться, что умеет его определять.

## Обязательные правила

- Один внешний радиус у `.main`; внутренние панели без своих радиусов, фонов и теней.
- Никаких клавиатурных подсказок и `title` с Shift/Ctrl/Esc в мобильных листах. Только действие: «Удалить», а не «Удалить (Shift — без вопроса)».
- Никаких ложных селектов: если кнопка не переключает значение, у неё не должно быть стрелки вниз. Действия — long press или bottom sheet.
- Никаких десктопных hover-иконок в строках. На сенсорном экране — long press и лист действий.
- Touch target не меньше 44×44, лучше 48×48.
- Никаких белых полосок-маркеров активного хаба на телефоне.
- Нижняя навигация — только компактный режим. На Workspace — rail; не дублировать оба.
- Уведомления — отдельный экран/вкладка, не колокольчик в шапке.
- Верхние «назад/вперёд» окна в PWA скрыты.
- Тёмная/светлая тема проверяется отдельно; фон не должен съедать контраст текста.
- Обои: отдельный портретный кроп для телефона, широкий кадр для фолда. Не растягивать landscape-кадр через `cover` без art direction.
- Анимации уважают `prefers-reduced-motion`; переходы короткие и не мешают чтению.

## Матрица проверки

Минимум:

```text
320×568   маленький телефон
360×800   телефон
390×844   телефон
412×915   крупный телефон
844×390   телефон боком
344×882   фолд снаружи
396×935   флип раскрыт
673×841   фолд раскрыт
935×800   планшет/широкий
```

Для каждого режима:

- нет горизонтального скролла;
- правильный rail/sidebar/bottom nav;
- шапка не перекрывает safe area;
- composer и поля ввода не обрезаны;
- все 12 тем;
- скриншот в `_backup/ui33/`.

## Процесс

1. Снять матрицу до изменений.
2. Найти ошибку в конкретном форм-факторе.
3. Исправить CSS/JS, не ломая PC.
4. Добавить e2e на форм-фактор.
5. Переснять матрицу и полный сценарий.
6. Не выпускать релиз без отдельного разрешения.
