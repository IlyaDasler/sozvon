# Паритет Go-сервера «Созвона»

Цель: рабочее приложение в бете работает на Go вместо Node, без регрессий и без релиза
клиента 3.0 до явного согласия владельца.

## Перед началом

1. Проверить, что запущено: `Get-Process sozvon-server-go`, `http://127.0.0.1:3000/api/health`.
2. Собрать: `go build -o sozvon-server-go.exe .` в `sozvon/server-go` с окружением:
   `GOCACHE=<workspace>\_tools\go-cache`, `GOTMPDIR=...\go-tmp`, `GOPATH=...\gopath`,
   `GOPROXY=https://goproxy.cn,direct`, `GOSUMDB=off`.
3. Запускать сервер с `DATA_DIR=<workspace>\_e2e\data`, `MAIL_TEST_FILE=...\mail.log`,
   `LINK_PREVIEW_ALLOW_PRIVATE=1`.
4. Если нужны почтовые коды и превью — эти переменные обязательны, иначе сценарии падают.

## Прогон e2e

Команда (из корня workspace):

```
cmd /c "set "ELECTRON_RUN_AS_NODE=" && "<node>" .\_tools\run-e2e.js <наборы>"
```

`ELECTRON_RUN_AS_NODE` обязательно снять, иначе Electron работает как Node и всё виснет.
Логи: `_backup\e2e\<набор>.log`. Скриншоты: `_backup\e2e`.

Базовый набор для регрессии: look, layout, spacing, friends, hubs, chat, room, threads,
status, call, group-call, two-factor, typing, unread, sessions, e2ee, journey, oauth, scenarios.
Остальные — по задаче.

## Как разбирать расхождения

- Сначала проверить на **Go-сервере** с чистой/копийной базой. Если падает и там —
  это тест или клиент, а не паритет. Зафиксировать это в отчёте.
- Не верить логам на слово: смотреть реальные HTTP-запросы и ответы, состояние БД, события WS.
- Типичные ловушки, уже пойманные:
  - вложенный SQL-запрос внутри открытых `rows` или транзакции вешает весь сервер
    (одно соединение SQLite) — сначала собрать строки, закрыть, потом догружать;
  - `NULL` в сканируемое `int64` (например, `read_id`) даёт пустой ответ — `COALESCE`;
  - членство в комнатах — `room_members`, как в Node; при вступлении в канал и создании
    комнаты туда добавляются все участники, иначе не работают кик и ротация ключей;
  - события `room:updated`/`hub:updated` нужны после каждого изменения прав и состава;
  - медиа отдавать только с `Seek(0)` после чтения заголовка, иначе файл обрезан на 512 байт;
  - `description`/`preview` в ответах должны быть объектами или `null`, не строками.
- После каждой правки — сборка, `go test ./...`, регрессия затронутых наборов.

## Медиа и LiveKit

- `/api/ice`: STUN + TURN с временными данными (HMAC-SHA1), как в Node.
- Пропуск LiveKit: JWT HS256, `iss`, `sub`, `video.room`, `roomJoin`, `canPublishSources`.
- Живая проверка: admin-пропуск Go против реального медиасервера (`ListRooms` должен дать 200).
- SFU включается по числу **участников комнаты**, а не сидящих в голосе.
- Для проверки SFU можно поднять временный Go-сервер на VPS с пустой базой и SSH-туннелем;
  после проверки удалить бинарник, данные и процесс. Прод-базу не трогать.

## Дисциплина

- Никаких релизов и изменений прод-клиента без прямого разрешения.
- Go — единственный сервер; Node-сервер в проекте отсутствует.
- Незавершённое не коммитить; после зелёного прогона — коммит и запись в `STATUS.md`
  с числами: какие наборы прошли, что осталось, что не проверено.
- В отчёте отделять проверенное от непроверенного; не выдавать «должно работать» за результат.
